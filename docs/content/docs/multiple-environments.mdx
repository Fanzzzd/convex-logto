This page uses the runtime `configQuery` setup from
[Quick start](/docs/quick-start). In that mode the frontend pulls public Logto
config from Convex, so **the only thing that varies per environment is the
Convex deployment it points at** (which you already set via
`VITE_CONVEX_URL`). The frontend has no Logto env vars to manage. With the
default static `config`, set the two public Logto values in each frontend
environment instead.

## Single-source config (recommended)

Create one Logto app per environment (dev / staging / prod — best practice, so
tokens can't cross environments), then set each deployment's env once:

```bash
# dev deployment
npx convex env set LOGTO_ENDPOINT https://your-logto.example.com
npx convex env set LOGTO_APP_ID   <dev-app-id>
# production deployment
npx convex env set --prod LOGTO_ENDPOINT https://your-logto.example.com
npx convex env set --prod LOGTO_APP_ID   <prod-app-id>
# staging: target that deployment the same way
```

With `configQuery`, the same frontend artifact works everywhere. Only the Convex
deployment selected by `VITE_CONVEX_URL` changes; each deployment serves its own
public Logto configuration.
