# Session mode returns token claims, not tokens, unless the app opts in, and never the refresh token

Aligning with `@logto/react`'s surface means offering `getAccessToken` / `getOrganizationToken`, but session mode exists precisely so the browser holds nothing long-lived: only the component has the Logto refresh token, and only it can mint a Resource token or Organization token at all. Rather than choose between literal SDK parity and that premise, custody is a setting: by default the component mints the token server-side and hands back only its **claims** (organization roles and scopes, resource scopes), so an app can authorize without a second bearer ever entering `window`; `exposeAccessTokens` opts into receiving the token string for callers who must reach a non-Convex API from the browser, accepting that it is one more thing XSS can steal. The refresh token has no such setting in either mode; exposing it collapses session mode into bridge mode and voids [ADR 0001](./0001-logto-session-component.md), and re-exporting bridge mode's `getRefreshToken` would make that an accident rather than a decision.

Convex itself never sees any of these: it validates the Short bearer (the ID token). An Organization token is audienced `urn:logto:organization:{id}` and typed `at+jwt`, both of which Convex rejects. Most of what applications actually authorize on needs no token flow at all, though: Logto maps `urn:logto:scope:organizations` to an `organizations` claim and `urn:logto:scope:organization_roles` to an `organization_roles` claim **in the ID token**, and Convex's `UserIdentity` passes unknown claims through, so membership and organization roles arrive in `ctx.auth.getUserIdentity()` for free. Only fine-grained organization *permissions*, which Logto puts nowhere but the Organization token, need the exchange.

## Consequences

- `resources` on `logtoSessionApi()` is no longer on a removal path: it becomes the input to the server-side token exchange. Its "will go in the next major" deprecation was withdrawn before it ever shipped.
- The default surface diverges from `@logto/react` by shape (claims, not tokens) while covering the same capability. Documenting that difference is part of the cost.
- Bridge mode can already do all of this through `useLogto()` directly. What this library adds there is a consistent re-export, not new capability, with `getRefreshToken` deliberately left out.
